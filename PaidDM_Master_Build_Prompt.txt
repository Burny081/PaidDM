ROLE You are the lead full-stack engineer building PaidDM from scratch.

PaidDM is a simple paid-messaging platform: “Pay to get your message
seen.”

A user logs in with X (Twitter), receives an embedded crypto wallet,
creates a public PaidDM profile, and can receive paid private messages
from other users.

For V1, keep the product extremely simple. The goal is a fully
functional TESTNET MVP with $0 of the developer’s own money.

PRODUCT

Name: PaidDM

Core idea: A user can pay another user/creator to send them a private
message.

Example: Creator: @idris PaidDM page: https://paiddm.xyz/@idris Price:
$2

Sender: 1. Opens the creator’s PaidDM page 2. Writes a private message
3. Clicks Pay & Send 4. Completes the blockchain transaction 5. Payment
is confirmed 6. The message becomes visible in the creator’s dashboard

The creator can then read and reply.

PRIVATE MESSAGE STORAGE

Message content is OFF-CHAIN.

Never put message text on Robinhood Chain.

Possible on-chain information: - sender wallet - creator wallet -
amount - token - message/payment ID hash - transaction event

Database contains: - encrypted message content - sender - recipient -
timestamp - payment status

Use TLS in transit and encryption at rest.

Only the sender and intended creator should access the message.

SMART CONTRACT

Create the smallest secure contract possible.

Concept: payForMessage(creator, amount, messageId)

The contract: 1. verifies amount 2. verifies creator is valid 3.
transfers supported ERC-20 token from sender 4. optionally splits
platform fee 5. transfers creator portion to creator 6. emits an event
7. prevents replay/double payment where appropriate

Example event: PaidMessage(bytes32 indexed messageId, address indexed
sender, address indexed creator, uint256 amount)

The message ID is an identifier/hash, NOT message content.

Use OpenZeppelin SafeERC20.

For V1, keep the platform fee at 0% unless implementing a fee adds no
unnecessary complexity.

Avoid unnecessary upgradeability.

Avoid complicated refund logic in V1.

PAYMENT MODEL

Example: Creator price: $2

Sender: - holds testnet token - pays $2 - pays blockchain gas in testnet
ETH

Creator: - receives the token directly if the contract pushes payment -
does not need a separate claim transaction

PaidDM backend: - watches/polls blockchain - independently verifies
transaction - verifies correct contract - verifies correct token -
verifies sender - verifies creator - verifies amount - verifies
message/payment ID - verifies confirmations - marks payment PAID

Never mark a message as paid merely because the frontend says the
transaction succeeded.

PAYMENT VERIFICATION

Backend must check: 1. Transaction exists 2. Transaction is on expected
Robinhood Chain testnet 3. Transaction succeeded 4. Contract is the
expected PaidDM contract 5. Token is the expected configured token 6.
Correct payment event exists 7. messageId matches database record 8.
creator matches expected wallet 9. sender matches expected wallet 10.
amount is sufficient 11. payment has not already been used

Only then set messages.payment_status = PAID.
